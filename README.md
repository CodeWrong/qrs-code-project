# C 语言每日练习

这个仓库用于记录每日 C 语言学习内容，包括常规练习、错题复写，以及针对个人疑惑所做的小型测试。

仓库以日期作为主要整理顺序，并在文件名中标明内容类型和主题。这样既方便每天直接开始编写代码，也方便以后按日期、类型或知识点查找。

## 目录结构

```text
qrs-project/
├─ daily/
│  └─ 年份/
│     └─ 月份/
│        └─ 年-月-日/
│           ├─ 01-practice-topic.c
│           ├─ 02-review-topic.c
│           └─ 03-test-topic.c
├─ .gitignore
└─ README.md
```

例如，2026 年 8 月 1 日的代码存放在：

```text
daily/2026/08/2026-08-01/
```

## 内容类型

文件名使用以下三种类型：

| 类型 | 含义 | 使用场景 |
| --- | --- | --- |
| `practice` | 常规练习 | 第一次完成课程题目或日常练习 |
| `review` | 错题复写 | 发现原练习有错误后，重新独立完成 |
| `test` | 疑惑测试 | 验证语法、边界情况或自己的想法 |

## 文件命名

统一使用：

```text
序号-类型-主题.c
```

例如：

```text
01-practice-for-loop.c
02-review-array-boundary.c
03-test-pointer-address.c
```

命名约定：

- 序号使用两位数字，按照当天的编写顺序排列。
- 类型固定使用 `practice`、`review` 或 `test`。
- 主题使用简短的英文单词，多个单词之间用连字符连接。
- 每道题或每个测试单独保存为一个 `.c` 文件。

## 源码注释模板

新建文件时，可以复制下面的文件头：

```c
/*
 * 类型：practice
 * 主题：题目主题
 * 日期：2026-08-01
 *
 * 题目：
 * 在这里简要描述题目。
 */
```

错题复写建议额外记录原来的问题和修正结论：

```c
/*
 * 类型：review
 * 主题：题目主题
 * 日期：2026-08-01
 *
 * 原题：
 * 在这里简要描述题目。
 *
 * 原因：
 * 记录上一次出错的原因。
 *
 * 结论：
 * 记录这次复写掌握的要点。
 */
```

疑惑测试应写清想验证的内容和最终结果：

```c
/*
 * 类型：test
 * 主题：测试主题
 * 日期：2026-08-01
 *
 * 疑问：
 * 写下准备验证的问题。
 *
 * 结论：
 * 测试完成后补充结论。
 */
```

## 每日使用步骤

1. 在对应年月下创建当天的日期目录。
2. 根据当天已有文件确定下一个序号。
3. 按照“序号-类型-主题”创建源码文件。
4. 填写文件头，然后编写、编译和运行代码。
5. 如果原练习后来被发现有误，保留原文件，并在复写当天新建一个 `review` 文件。

## 整理原则

- 文件按照首次编写日期归档，不因之后的小修改而更换日期。
- 错题复写保存为新文件，不覆盖原练习，以便观察自己的改进过程。
- 知识点写在文件名和注释中，暂时不额外建立“循环”“数组”等分类目录。
- `.exe` 等编译产物不纳入版本管理，需要时由源码重新编译。
- 目录中的源码保留当时的练习结果；整理文件时不顺便修改代码逻辑。
